# Model calls go through OpenRouter, direct DeepSeek kept as backup

Status: accepted. Built (openrouter issues 02 to 06, and 08): replies, tool calls and photos go through OpenRouter, `openrouter` is the default `CHAT_MODEL_ADAPTER`, Admins can pick four Claude models (`anthropic/claude-haiku-5.5`, `anthropic/claude-sonnet-5.5`, `anthropic/claude-opus-5.5`, `anthropic/claude-fable-5.2`) beside the DeepSeek ones, and Claude calls use prompt caching. Amends ADR-0003's adapter list.

Every model call went straight to DeepSeek, so trying another provider meant a new adapter per provider. Model calls now go through one OpenRouter adapter behind the `ChatModel` and `PhotoViewer` ports, using the operator's own provider keys (BYOK). A new model is then just a new name in Platform Settings. The adapter is plain `httpx` against OpenRouter's Chat Completions API, not LangChain, so we control the request (`reasoning`, `cache_control`, provider routing) and read the reasoning text straight from the reply. It sends the model name exactly as saved, and the thinking switch becomes `reasoning: {enabled: true|false}`.

The direct DeepSeek adapter stays, chosen with `CHAT_MODEL_ADAPTER=deepseek`, as a way out if OpenRouter is down. It turns OpenRouter DeepSeek names into direct ones and refuses other providers' models.

## Considered Options

- **One adapter per provider (DeepSeek, Anthropic, …).** Rejected: each new provider is new code, tests and keys to wire.
- **LangChain's OpenAI-format client pointed at OpenRouter.** Rejected: it drops the `reasoning` field and is reported to drop `cache_control` silently.
- **Automatic fallback to direct DeepSeek when OpenRouter fails.** Rejected for now: the switch is a manual setting.

## Consequences

- Calls must never spend OpenRouter credits. On each BYOK key in the OpenRouter account, "Shared capacity fallback" is set to "Never use any other provider or key for this key's models", and the account's privacy settings allow providers that may train on inputs, or DeepSeek's own servers are refused (manual steps; see `docs/DEPLOYMENT_GUIDE.md`).
- Each request allows only the model's maker to answer (`provider: {only: [<the part of the name before "/">]}`), because our keys are the makers' keys. Without it, a model its maker does not serve under that name is quietly answered by another host on credits; with it, the call fails. This is why the saved DeepSeek names are the dated ones DeepSeek itself serves. A model whose maker is not also its OpenRouter provider can't be called until this rule is widened.
- The adapter logs a warning when a reply's usage says it was not paid with our own key.
- `OPENROUTER_API_KEY` is read through config. A chosen adapter without its key fails at startup; `DEEPSEEK_API_KEY` is only needed for the `deepseek` backup.
- Model Prices are still set by Admins per model name; OpenRouter's reported cost is not used.
- With thinking on, a Claude model decides for itself whether a call needs thinking. An easy call comes back with no reasoning text, so an empty reasoning in the Model Call Log is not an error.
- Sonnet 5.5, Opus 5.5 and Fable 5.2 always think: OpenRouter refuses `reasoning: {enabled: false}` for them ("Reasoning is mandatory"). They are named in the Platform Setting `models_that_always_think`, kept beside `models_that_cannot_think` and filled by the seed and migration 0099. OpenRouter's model list does not say which models always think. For a core service on such a model, the Dashboard shows the thinking switch on and locked (a pop-up says why), a save that would turn thinking off is refused, changing to the model saves thinking as on, and every call is made with thinking on whatever is saved (`thinking_to_use`). The two calls that name their own thinking follow the same rule (`thinking_for_model`): the Check-in "brought up" check and the Judge. The adapter holds no model names and sends `reasoning: {enabled: ...}` as it is told, so a caller that skips the rule and asks such a model for thinking off gets OpenRouter's error. A new model that always thinks must be added to that list (openrouter issue 11).
- A model that can't think is named in the Platform Setting `models_that_cannot_think`, kept beside `available_models` and filled by the seed or a migration (empty today: every listed model can think). It is not read from OpenRouter's model list, so saving a setting needs no network call and the rule also holds on the `deepseek` backup. For a core service on such a model, the Dashboard shows the thinking switch off and locked, a save that would turn thinking on is refused, changing to the model saves thinking as off, and every call is made with thinking off whatever is saved (`thinking_to_use`). A new model that can't think must be added to that list (openrouter issue 07).
- Prompt caching: a Claude model (any `anthropic/` name) gets its instructions sent as a text part with `cache_control: {type: ephemeral}`, which Anthropic keeps for 5 minutes. Other models get no marker; DeepSeek caches the same start of a request by itself. For every call the adapter logs, at INFO, how many prompt tokens were read from the cache and how many were written to it (`usage.prompt_tokens_details`), and the backend prints that line.
- The cache only helps a service whose instructions stay the same from one call to the next. Safeguard, Understanding and Reply plan have fixed instructions and get cache hits. The Reply's instructions end with the plan for that one message, so the `ChatModel` port takes instructions as two texts: `instructions`, which stay the same from call to call, and an optional `message_instructions` made for that one call (openrouter issue 09). The Reply gives the Persona, the response prompt and the priority order as the first, and its sections (from "## 1.") as the second. For a Claude model the adapter marks only the first, in a text part of its own, so the tools and the fixed part are read from the cache; the second follows unmarked. For any other model the two are joined, fixed part first. The Model Call Log keeps them as one text. A Claude model caches a marked block only from a minimum size: 512 tokens for Haiku 5.5, Sonnet 5.5, Opus 5.5 and Fable 5.2 (Anthropic's prompt caching docs, 25 Nov 2026). The Reply's tools and fixed part are well above it. The Reply's cache still misses when its tools change from one message to the next, because tools come before the instructions: `send_photo` and `ask_about_photo` list the photos that matter for the message in their descriptions, and `send_sticker` lists the stickers (openrouter issue 13).
