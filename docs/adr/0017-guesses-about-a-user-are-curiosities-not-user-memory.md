# Guesses about a User are Curiosities, not User Memory

To get to know a User in depth, Zeph needs to hold things it suspects but isn't sure of ("their mum lives in Singapore") and check them gently, through the Get curious Move, a woven-in question or a Curiosity Check-in. We keep these guesses as Curiosities, each with how sure Zeph is, rather than in User Memory. A guess isn't a memory yet: showing Users half-formed beliefs about themselves as if they were known would mislead them, and stating one as fact would make Zeph wrong out loud. Once the User answers, the guess is closed and what they said is kept as a Memory Item when the Conversation ends. The User Portrait's open questions move out for the same reason, so the Portrait holds only what Zeph is fairly sure of.

## Considered Options

- **A certainty marker on each Memory Item.** Precise, but guesses would show on the Dashboard as memories, and every memory-keeping step and page would have to carry it.
- **Open questions in the User Portrait.** No new data, but the Portrait is seen by Users, so guesses would be shown to them.
- **A separate store of guesses.** Same lifecycle (waiting, raised, how they took it, closed), privacy rules and delivery routes as Curiosities, so two things would compete and overlap.

## Consequences

- Users don't see guesses, like the rest of Curiosities; Delete My Data and Account Deletion remove them, and deleting the Memory Item or Life Thread one came from removes it.
- The reply never states a guess as fact; it only checks it.
- Guesses share the Curiosity waiting limit and per-Conversation raise limit with other Curiosities. A Get curious question made in the moment, not from a saved Curiosity, doesn't count toward the raise limit.
