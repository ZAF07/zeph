# 34 — Reflections: Zeph guides a User to reflect on a confirmed Pattern

Status: needs-info
Track: shared
Blocked by: 39 (replies are shown the Patterns Zeph told the User)

## Parent

`.scratch/pattern-pipeline/PRD.md`. The owner's idea, raised on 25 Nov 2026 while answering issue 30. Design so far: `docs/pattern-pipeline/README.md`.

## Why

A confirmed Pattern is hardly used. It goes into the Portrait, and (after issue 39) replies may name it when a story fits. Zeph still does nothing active with what it learned, and the owner wants Zeph to work toward a goal, not wait.

## The owner's idea

A new feature called **Reflections**. With a confirmed Pattern, Zeph guides or prompts the User through reflecting on it:

- what could be better;
- how did you feel;
- what do you feel now, looking back;
- and more like these.

## Needs the owner's decisions before any solution

Don't plan or build this yet. Go through it with the owner (`/grill-with-docs`), then write a PRD or a plan here.

Questions to start from:

1. What is a Reflection for: seeing the Pattern more clearly, trying something different, or both?
2. When does Zeph start one: right after a Pattern is confirmed, when it next shows up in a story, or on a schedule?
3. In chat, as a Check-in, or both? How often at most?
4. Who writes the questions: a fixed set per Pattern Type in the catalog (like Predictions), an Admin-managed list (like Thought Experiments), or the model?
5. Is what the User says in a Reflection kept (and shown on the Patterns tab), or only used in that Conversation?
6. Does a Reflection lead to something to try (a small experiment), and does Zeph follow up on it?
7. How does a User say "not now" or "never", and does backing off hold Reflections?
8. Is it a Feature of its own, switched per User like the three Pattern Features?

## Acceptance criteria
